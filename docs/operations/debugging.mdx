# Debugging

A Durable Object on OpenOrange is a Rivet Actor, so you debug it with Rivet's tools: logs,
the Rivet dashboard, and the Rivet API.

## Quickstart

<Steps>

<Step title="Check the project">

```sh
orange doctor
```

</Step>

<Step title="Run with debug logs">

RivetKit's logs print next to your Worker's output.

```sh
orange dev --log-level debug
```

</Step>

<Step title="Match the symptom">

The [Debug an object](../modules/durable-objects#debug-an-object) table covers the common
cases, such as an object that never sleeps.

</Step>

</Steps>

## Find an object's actor

Each object is an actor named after its class, such as `greeter-5c8cd02c`. The Rivet dashboard
lists them, and so does the Rivet API:

```sh
curl -H "authorization: Bearer $RIVET_TOKEN" "https://<engine-host>/actors?namespace=<namespace>&name=<actor-name>"
```

## Read the logs

Rivet Cloud shows your runners' output on the cluster's Logs page. To add RivetKit's info logs,
deploy with:

```sh
orange deploy --var RIVET_LOG_LEVEL:info
```

<AiContext summary="Actor names, API calls, and log details">

#### Object to actor

| Durable Object | Rivet Actor |
|---|---|
| Class | Actor name: the class in kebab case and a short hash, such as `greeter-5c8cd02c` |
| ID | Actor key |

The [Debug an object](../modules/durable-objects#debug-an-object) symptom table also covers an
RPC call that is too large.

#### Rivet API

On Rivet Cloud, the Rivet dashboard lists the actors of your cluster. Anywhere, the Rivet API
lists them. `<engine-host>`, `<namespace>`, and the token are the parts of `RIVET_ENDPOINT`.
These calls list the actor names, list the actors of one name, and check one actor:

```sh
curl -H "authorization: Bearer $RIVET_TOKEN" "https://<engine-host>/actors/names?namespace=<namespace>"
curl -H "authorization: Bearer $RIVET_TOKEN" "https://<engine-host>/actors?namespace=<namespace>&name=<actor-name>"
curl -H "authorization: Bearer $RIVET_TOKEN" "https://<engine-host>/gateway/<actor-id>/health"
```

#### Logs

- Self-hosted, read the container's output.
- RivetKit's info logs include the lines that show
  [what keeps an object awake](../modules/durable-objects#find-what-keeps-an-object-awake).
- A Rivet error has a ray ID, such as `actor.not_found#<ray id>`. Search the logs for it.
- For traces and metrics, see [Monitoring](./monitoring).

</AiContext>
