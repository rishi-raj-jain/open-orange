# Regions

Your Worker and its Durable Objects run in the region where you deploy them. Put that region
next to your database.

## Quickstart

<Steps>

<Step title="Find your database's region">

Most backends talk to one database. A Worker next to it answers faster than a Worker at the
edge, which crosses the internet on every query.

</Step>

<Step title="Create the cluster there">

On Rivet Cloud, you pick the cloud provider and region when you create the cluster.

</Step>

<Step title="Deploy">

In a cluster with several regions, `--region` picks the region of the runner pool.

```sh
orange deploy --region <region>
```

</Step>

</Steps>

## Self-host

Your Rivet Engine runs in one region, and your objects and their data run there.

<AiContext summary="Placement, location hints, and the edge">

#### Placement

- Each Durable Object is one Rivet Actor. It lives in one region for its lifetime, and its
  storage stays in that region.
- An object does not move between regions. A call from another region crosses the network to
  it, like any other remote call.
- Location hints and jurisdictions do not change where an object runs. OpenOrange checks them,
  then ignores them for placement.

#### The edge

Stateless Worker requests can run in as many regions as you deploy runners to. For Durable
Objects, an upcoming Rivet update adds multi-region support, including edge regions. Until then,
keep an app's Durable Objects in one region.

</AiContext>
