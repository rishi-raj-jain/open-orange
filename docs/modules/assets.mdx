# Static assets

Orange serves the files in your Worker's `assets` directory straight from
disk, and routes each request to a file or to your Worker as Cloudflare does.
Assets are files in your project, so they deploy with it and there is nothing
to migrate.

## Quickstart

This serves a single-page app from `public/` and sends `/api/*` to your
Worker.

<Steps>

<Step title="Point assets at a directory">

Add `assets` to `wrangler.jsonc`.

```jsonc
{
  "name": "assets-spa",
  "main": "src/index.ts",
  "compatibility_date": "2026-09-03",
  "assets": {
    "directory": "./public",
    // Unknown paths serve index.html, so the browser app can route them.
    "not_found_handling": "single-page-application",
    // API requests always reach the Worker, even when no asset matches.
    "run_worker_first": ["/api/*"]
  }
}
```

</Step>

<Step title="Write the Worker for the API">

Only requests that match `run_worker_first` reach this Worker. Your files
answer everything else.

```ts
export default {
  async fetch(request): Promise<Response> {
    const { pathname } = new URL(request.url);
    if (pathname === "/api/hello") {
      return Response.json({ message: "Hello from the Worker" });
    }
    return Response.json({ error: `No API route for ${pathname}` }, { status: 404 });
  },
} satisfies ExportedHandler;
```

</Step>

<Step title="Run it">

`orange dev` serves the Worker on port 8787.

```sh
orange dev
```

Open `http://localhost:8787/about` in a browser: the app's `index.html` loads.
An API route that does not exist gets the Worker's 404, never `index.html`.

```sh
curl localhost:8787/api/hello     # {"message":"Hello from the Worker"}
curl localhost:8787/api/missing   # 404 {"error":"No API route for /api/missing"}
```

</Step>

</Steps>

## How it works

- A request whose path matches `run_worker_first` goes to your Worker.
- Any other request gets its matching file. When no file matches,
  `not_found_handling` or your Worker answers.
- Orange reads the directory on each request, so a new or changed file serves
  without a restart.

<AiContext summary="Compatibility, limits and details">

#### Compatibility

**Status: Partial.** Orange serves the assets directory from local files.

| Feature | Status | Notes |
| --- | --- | --- |
| `html_handling` | Supported | All four modes, with their `307` redirects. |
| `not_found_handling` | Supported | `single-page-application`, and `404-page` with the nearest `404.html`. |
| `run_worker_first` | Supported | `true`, or patterns with `*` and `!/` exclusions. |
| `assets.binding` and `env.ASSETS.fetch()` | Supported | Follows redirects like any Fetcher. |
| Assets-only Workers | Supported | A project without `main`. |
| `.assetsignore` | Supported | `.gitignore` syntax. |
| `ETag`, `If-None-Match`, and `Cache-Control` | Supported | |
| `_headers` and `_redirects` | Not supported | |
| Workers Sites (`site`) | Not supported | |
| The router's `/_next/image` and `/_image` content-type checks | Not supported | |

One difference reaches most projects:

- **`_headers` and `_redirects` have no effect,** and `orange dev` warns at
  startup when the directory has one. Set those headers and redirects in the
  Worker, and list their paths in `run_worker_first`, so the Worker sees the
  requests before assets answer them.

#### Limits

| What | Limit | What happens over it |
| --- | --- | --- |
| Size of one file | No limit set by Orange. Cloudflare's is 25 MiB. | |
| Number of files | No limit set by Orange. Cloudflare's is 100,000. | |
| Methods for an asset path | `GET` and `HEAD` | Assets answer `405 Method Not Allowed`. |

#### What Orange reads

Orange reads `assets` as `wrangler dev` does, with these differences:

| In your project | On Orange |
| --- | --- |
| `assets.directory` outside the project | `orange dev` serves it. `orange deploy` stops with `orange deploy copies the project directory only, so assets must be inside it: <directory>`, because it copies only the project directory. |
| `site`, `legacy_assets`, or `pages_build_output_dir` | The configuration does not load: `Unsupported Wrangler configuration: <keys>`. |

#### Routing

Orange routes each request like Cloudflare's router Worker, then serves it
like the asset Worker, from the files on disk:

1. A path that matches a `!/` pattern in `run_worker_first` goes to assets.
2. A path that matches another pattern, or any path with
   `run_worker_first: true`, goes to the Worker.
3. Otherwise assets answer when a file matches, and the Worker runs when none
   does. An assets-only Worker serves every request from assets.

- A pattern matches the whole path, and `*` matches any characters,
  including `/`.
- `orange dev` and `orange serve` both serve assets.

#### Configuration reference

`directory` resolves against the configuration file.

| Key | Default | Values |
| --- | --- | --- |
| `directory` | Required | A path, resolved against the configuration file |
| `binding` | None | The name of `env.<binding>` |
| `html_handling` | `auto-trailing-slash` | `auto-trailing-slash`, `force-trailing-slash`, `drop-trailing-slash`, `none` |
| `not_found_handling` | `none` | `single-page-application`, `404-page`, `none` |
| `run_worker_first` | None | `true`, `false`, or an array of patterns |

Errors that stop config load, with Wrangler's text where Wrangler has one:

| Configuration | Error message |
| --- | --- |
| `assets` that is not an object | `assets must be an object` |
| No `directory` | ``The `assets` property in your configuration is missing the required `directory` property.`` |
| An empty `directory` | `The assets directory cannot be an empty string.` |
| An unknown `html_handling` | `assets.html_handling must be one of auto-trailing-slash, drop-trailing-slash, force-trailing-slash, none` |
| An unknown `not_found_handling` | `assets.not_found_handling must be one of 404-page, none, single-page-application` |
| `run_worker_first` that is not a boolean or an array | `assets.run_worker_first must be a boolean or an array of strings` |
| An empty `run_worker_first` array | ``No `run_worker_first` rules were provided; must provide at least 1 rule.`` |
| A pattern that does not start with `/` or `!/` | ``Invalid routes in `run_worker_first`:`` and a line for each, such as `'api/*': rules must start with '/' or '!/'` or `'!api': negative rules must start with '!/'` |
| Only `!/` patterns | ``Only negative `run_worker_first` rules were provided; must provide at least 1 non-negative rule`` |
| `binding` without `main` | `Cannot use assets with a binding in an assets-only Worker.` |
| `run_worker_first` without `main` | `Cannot set run_worker_first without a Worker script.` |

- `run_worker_first: true` without `binding` loads with the warning
  `run_worker_first=true set without an assets binding. Every request runs the Worker, which cannot fetch assets without assets.binding.`
- `orange dev` checks the directory after the custom build in `build.command`.
  A missing directory stops it with
  `The directory specified by the "assets.directory" field in your configuration file does not exist:`,
  and a file stops it with
  `The path specified by the "assets.directory" field in your configuration file doesn't point to a directory:`.
- The warning for `_headers` is
  `open-orange does not apply the assets _headers file yet, so its rules have no effect.`
  `_redirects` gets the same warning.
- A configuration with neither `main` nor `assets` fails with
  `Wrangler configuration must resolve a Worker entrypoint`.
- The compatibility flags `assets_navigation_prefers_asset_serving` and
  `assets_navigation_has_no_effect` apply, so Orange does not warn about
  them.
- `orange migrate prepare` adds `/__migrate/*` and `/__migrate-d1/*` to
  `run_worker_first` in `wrangler.migrate.jsonc`, so the migrator's routes
  reach the Worker before assets. A `run_worker_first: true` stays as it is.
  See [Migrate from Cloudflare](../migrate).

#### HTML handling

The handler is a port of Cloudflare's asset Worker. It redirects with `307`
only when nothing exists at the destination and the destination would serve
the same file. The query string is kept.

| Mode | `/about.html` serves at | `/blog/index.html` serves at |
| --- | --- | --- |
| `auto-trailing-slash` | `/about` | `/blog/` |
| `force-trailing-slash` | `/about/` | `/blog/` |
| `drop-trailing-slash` | `/about` | `/blog` |
| `none` | `/about.html` only | `/blog/index.html` only |

- Paths are decoded before the lookup, so non-ASCII and optionally encoded
  characters match. A request for another spelling of the canonical path gets
  a `307` to it.
- Under `drop-trailing-slash`, the root keeps its slash.
- With both `/foo.html` and `/foo/index.html`, `force-trailing-slash` keeps
  `/foo.html` at its own path, and `drop-trailing-slash` keeps
  `/foo/index.html` at its own path.

#### Not-found handling

- `single-page-application` serves `/index.html` with `200`.
- `404-page` serves the nearest `404.html` in the path's directory or a parent
  directory, with `404`.
- `none` answers `404` with no body, or runs the Worker.
- For a Worker with `main` and no `run_worker_first` patterns, the router
  applies `not_found_handling` only to a request with
  `Sec-Fetch-Mode: navigate`, and only while
  `assets_navigation_prefers_asset_serving` is on, as on Cloudflare. That flag
  is on from the compatibility date 2025-04-01, and
  `assets_navigation_has_no_effect` turns it off. Otherwise a missing path
  runs the Worker, so a `fetch()` from your app to a missing path reaches the
  Worker.
- With `run_worker_first` patterns, in an assets-only Worker, and in
  `env.ASSETS.fetch()`, `not_found_handling` applies to every request.

#### Responses

- `ETag` is a strong ETag of 32 hex characters, from a SHA-256 of the file
  path and its modification time, as in `wrangler dev`. `If-None-Match` with
  it, strong or `W/`, gets `304`.
- `Content-Type` comes from the file extension. Text types get
  `; charset=utf-8`.
- `Cache-Control: public, max-age=0, must-revalidate`, unless the request has
  `Authorization` or `Range`.
- `CF-Cache-Status: HIT` on every asset response, as for local reads in
  `wrangler dev`.
- A request with `Range` gets the whole file with `200`.
- `HEAD` gets the headers and no body.
- `.assetsignore`, `_headers`, and `_redirects` are never served. A path with
  a `.` or `..` segment matches no asset.

#### Deviations

These add to the differences under [Compatibility](#compatibility) and
[Limits](#limits).

- Orange reads the directory on each request. `wrangler dev` builds its view
  of the directory when it starts.
