# Bindings

OpenOrange reads bindings from the same Wrangler configuration as `wrangler dev`.
Each binding is one of three kinds:

- **Runs as is:** OpenOrange implements the Cloudflare API. You set nothing.
- **Needs a service:** OpenOrange implements the Cloudflare API on a service
  that you supply, such as your SMTP server. You set one variable that points
  to it.
- **Not supported:** the binding loads, but Orange has no backend for it. The
  Worker loads, and `env.NAME` exists. Each method call throws an error that
  names the binding and suggests an alternative. Analytics Engine is the
  exception: `writeDataPoint()` accepts data points and drops them, as
  `wrangler dev` does.

`orange doctor` reports each binding of your project as one of these kinds. It does not
list variables (`vars`, `.dev.vars`, and `.env`), because they need nothing on Rivet.

Where a binding stores data depends on the command. Under `orange dev`, Rivet
Actors run on a local Rivet Engine, and data stays on your machine. Under
`orange deploy`, they run on your Rivet cluster. A service binding sends data
to the service that you set.

- Configuration that changes how the Worker runs, not what `env` contains, still stops `orange dev`
  with `Unsupported Wrangler configuration`.
- Examples are `streaming_tail_consumers` and `triggers.events`.
- `orange dev` accepts `containers` with a warning and runs `@cloudflare/sandbox` classes on a
  sandbox provider, such as E2B, Daytona, or Freestyle (see [Sandbox](./sandbox)).
- `orange dev` runs `triggers.crons` (see [Cron Triggers](./cron-triggers)) and delivers
  `queues.consumers` to the Worker's `queue()` handler (see [Queues](./queues)).

## Bindings that are not supported

`orange dev` marks each binding that is not supported in its binding table at startup, with what to use
instead on the next line:

```text
  Binding        Resource            Runs on
! env.IMAGES     Images              stub · calls throw
                                     See the OpenOrange bindings documentation for supported bindings.
```

The binding is a stub, and it is safe to pass around. `typeof env.IMAGES` is `"object"`, reading a
property returns a function, and awaiting the stub does not call it. Calling any
method throws an `Error` with the same message:

```js
await env.IMAGES.info(stream);
// Error: Images binding "IMAGES" is not supported by OpenOrange. ...
```

## What to use instead

Most bindings that are not supported have a replacement. Most replacements
use `fetch()` to an external service, or a Durable Object, which OpenOrange
runs as a Rivet Actor with SQLite storage and alarms.

### Other bindings

OpenOrange does not support these bindings. Change the Worker to call one of these
services instead:

| Binding | Service to use instead | How the Worker reaches it |
| --- | --- | --- |
| Vectorize | [pgvector](https://github.com/pgvector/pgvector) on [Neon](https://neon.com/docs/extensions/pgvector) or [Supabase](https://supabase.com/docs/guides/database/extensions/pgvector) | A [Hyperdrive](./hyperdrive) binding and a Postgres driver |
| Vectorize | [Qdrant Cloud](https://qdrant.tech/documentation/cloud/authentication/) | `fetch()` to `https://<cluster host>:6333`, with the `api-key` header |
| Vectorize | [Pinecone](https://docs.pinecone.io/guides/get-started/quickstart) | `fetch()` to the index host, with the `Api-Key` header |
| Vectorize, a few thousand vectors | SQLite in a Durable Object | Store the embeddings, and rank them by cosine similarity in JavaScript |
| Images | [Cloudinary](https://cloudinary.com/documentation/image_transformations) | `fetch()` to its upload and transformation URLs |
| Images | [imgproxy](https://imgproxy.net/) that you run | `fetch()` to its processing URLs |
| Analytics Engine | Your analytics store | `fetch()` to its ingest API |

## Variables and secrets

`orange dev` resolves variables with Wrangler's own `wrangler dev` logic:

1. It starts with `vars` from the Wrangler configuration.
2. It loads `.dev.vars.<env>` or `.dev.vars` next to the configuration file.
3. If neither file exists, it loads `.env`, `.env.local`, `.env.<env>`, and
   `.env.<env>.local`. Set `CLOUDFLARE_INCLUDE_PROCESS_ENV=true` to also load
   the process environment.
4. Loaded values become string bindings that replace `vars` with the same name.
5. If `secrets.required` is set, only the listed keys load, and `orange dev`
   warns about missing keys.

A `.dev.vars` entry named after another binding, such as a Secrets Store
binding, stays that binding's local value and does not replace it.

Secret values never become part of the version metadata ID.
